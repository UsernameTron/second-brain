    - Fresh date (age <= 14 days): checkStaleness returns null -> hook prints nothing.
    - Boundary: exactly 14 days old returns null (stale only when strictly > 14).
    - 15 days old: returns a warning string containing "CLAUDE.md", "15 days", and "/gsd:sync-docs".

    - No `> Last verified:` line present: returns a warning noting the date is missing/unparseable and still suggests /gsd:sync-docs.
  </behavior>
  <action>
    Create `.claude/hooks/staleness-check.js`:
    - `#!/usr/bin/env node` + `'use strict';`.
    - Export a pure function `checkStaleness(claudeMdContent, now)` returning a warning `string` or `null`:
      - Parse the date with `/^>\s*Last verified:\s*(\d{4}-\d{2}-\d{2})/m`.
      - No match -> return: `"[staleness] CLAUDE.md has no parseable 'Last verified:' date — a status block without a verifiable date is stale by definition. Run /gsd:sync-docs."`
      - Match -> `ageDays = Math.floor((now - parsedDate) / 86400000)`. If `ageDays > 14` return `"[staleness] CLAUDE.md status block is " + ageDays + " days stale (Last verified: " + date + "). Run /gsd:sync-docs to refresh."`; else return `null`.
    - Hook entrypoint guarded by `if (require.main === module) { ... }`: read `path.join(process.env.CLAUDE_PROJECT_DIR || process.cwd(), 'CLAUDE.md')`; on read error treat as unparseable (still a warning, never throw); call `checkStaleness(content, new Date())`; if it returns a string, write it with `process.stdout.write(msg + "\n")`; ALWAYS `process.exit(0)`. No `console.log` (ESLint bans it; stdout write is the hook contract).
    - `module.exports = { checkStaleness };` so Jest imports the core without spawning the process.
    Create `test/staleness-check.test.js` covering every case in <behavior>. Build fixtures as template strings containing `> Last verified: <date>`; pass a fixed `now` Date for determinism (never rely on the real clock).
  </action>
