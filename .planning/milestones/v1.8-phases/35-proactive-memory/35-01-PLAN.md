<objective>
Add a SessionStart hook that proactively injects a small, exclusion-gated digest of the
most relevant recalled memories into every new session's context.

Purpose: close the "memory compounds daily" loop on the read side — today memory is only pulled
when a human types `/recall`; this makes each new session start already aware of relevant prior
memories, without any manual action.
Output: `.claude/hooks/session-memory-inject.js` (fail-open, exit 0 always), a `sessionInject`
config block + schema, hook registration in `.claude/settings.json`, and pure-function tests.

This phase is pure integration glue over four already-hardened modules (`runRecall`, `checkContent`,
`loadExcludedTerms`/`loadConfigWithOverlay`, `voyage-health.isDegraded`). No new subsystem, no new
dependency.

Architecture decisions locked by the orchestrator (do not revisit):
1. SessionStart stdout DOES reach Claude's context (verified live in this repo). Use plain
   `process.stdout.write` like `staleness-check.js`; `exit 0` always.
2. Recall is called IN-PROCESS via `runRecall([...], { _internal: true })`, NOT by shelling to
   `scripts/recall.js`. This is a deliberate deviation from the ROADMAP wording ("shelling to
   scripts/recall.js") — same observable behavior, but the in-process `_internal:true` call is the
   clean root fix for the stats double-count risk (shelling has no way to pass `_internal`, so it
   would inflate `recall_count`/`recall_hits` on every session start and pollute the Phase 31
   compounding-trend verdict). It also avoids a second Node boot inside the latency-gated path.
3. Project-derived query = `path.basename(process.env.CLAUDE_PROJECT_DIR || process.cwd())`.
</objective>
