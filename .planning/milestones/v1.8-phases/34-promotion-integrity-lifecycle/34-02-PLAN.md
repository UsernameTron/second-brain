<objective>
Establish the `superseded-by::` / `stale::` entry convention on the read path. This is a prerequisite of the dream work: MERGE stamps sources with `superseded-by:: <newhash>` and STALE stamps `stale:: YYYY-MM-DD · <reason>`, and both must be downranked (not deleted) at read time so retrieval prefers the live/merged entry while provenance stays resolvable.

Purpose: superseded and stale entries stop competing for the top of recall results without ever being removed — golden-set hashes stay live, physical prune remains the year-archive sweep.
Output: readMemory parses the two fields; keyword search and Memory Echo apply a downrank penalty; superseded/stale entries remain returned, just lower.
</objective>

<constraints>
- Downrank is READ-TIME only. Never delete, never filter out — a superseded/stale entry must still appear in results, only with reduced rank. (Physical removal stays with the existing year-archive sweep — see DREAM-CONSOLIDATION-DESIGN.md failure-modes table.)
- No `console.log` in production code.
- Behavior for entries WITHOUT these fields must be byte-identical to today (guard the existing recall baseline — Phase 32 `npm run eval:recall` must not regress).
</constraints>
