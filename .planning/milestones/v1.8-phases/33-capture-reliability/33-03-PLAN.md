<objective>
Wire `src/utils/classifier-health.js` into `createLlmClient`'s local classify seam: count HTTP/shape/parse/timeout failures, extend fallback-to-Haiku to ALL of those classes, fast-path straight to Haiku once degraded, and enforce the per-night Haiku cap (skip + log, never throw).

Purpose: This is the behavior half of the resilience story. Today the local path only falls back on network/timeout and silently eats HTTP/parse errors as hard failures; a wedged local model still costs a 60s timeout on every single item. After this, three bad calls flip the client degraded so the rest of the night skips local entirely and goes straight to (capped) Haiku — the sweep keeps capturing instead of stalling.
Output: a hardened createLlmClient and updated pipeline-infra tests reflecting the new fallback contract.
</objective>

<locked_decisions>
- Fallback is EXTENDED to HTTP AND parse errors (roadmap: "extended to HTTP/parse errors"), plus timeout. This
  INTENTIONALLY inverts today's "does NOT fall back on HTTP 500 / parse / shape" behavior. The prior no-fallback
  design chose diagnostic purity; this phase chooses sweep resilience. Update the existing tests to match — do not
  preserve the old no-fallback assertions.
- Degraded semantics mirror voyage-health (3 consecutive → degraded window). While degraded, skip the local
  attempt entirely (don't pay the timeout) and go straight to Haiku.
- Per-night Haiku cap: when isHaikuCapReached(cap), return `{success:false, skipped:true, failureMode:'haiku-cap', error:...}`
  and logDecision('LLM_CLASSIFY','anthropic','SKIPPED', `nightly Haiku cap ${cap} reached`). NEVER throw — classify
  is contractually non-throwing (D-36); memory-extractor already handles `success:false`, so the sweep continues.
- The cap counts only Haiku FALLBACK calls (degraded-route or per-call-failure route). A clean local success does
  NOT increment it.
</locked_decisions>
